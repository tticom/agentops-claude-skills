Similarity is the `difflib` ratio of the two `SKILL.md` files, and identical or near-identical means 0.995 or higher. The comparison is against that cached revision, not a fresh fetch of upstream `main`.
- **Authorship:** origin is taken from git history at the pinned revision and from content comparison. A skill first authored by the local identities is class A; a skill first authored upstream, or whose text is materially the upstream text, is class B or C.
- **Classes:** A locally original and reusable; B derived from upstream (attributed or rewritten); C provided by upstream, not migrated; D specific to a retired harness; E specific to a single project; F obsolete.
- **Dispositions:** `migrated`, `consolidated`, `project-specific`, `upstream-provided`, `obsolete`, `blocked`.

## Migration limitations

- **Runtime validation:** no skill was exercised inside Claude Code or Codex in this change; see `docs/COMPATIBILITY.md` for what was and was not verified.
- **Hosting service:** the publication and dispatch helpers are tested against faked GitHub calls. No live PR, review or comment was created.
- **External tools:** the identity, review, handback and remediation helpers need `git` and an authenticated `gh`; the cleanup helper needs `git`.
- **Provenance:** `code-review` and `verified-implementation` carry a `NOTICE.md` with the upstream MIT notice for their derived passages. All other migrated skills were first authored by the local identities per the pinned history; that is a claim from history, not legal advice.
- **Not installed:** nothing was installed into any user environment, no project task authority or governance file was changed, and the source repository was not retired.
